架构ARCHITECTURE

一套支撑合规服务的技术底座

四层之间通过标准接口通信，任何一层升级都不必推倒重来。对客户来说，这意味着服务能持续演进，而不是每换一次技术就重做一次方案。

L1 基础设施层

弹性、按需、可恢复

以云平台承载弹性计算、分布式存储与安全网关，按业务量伸缩；配套加密服务与备份恢复机制，把「可用」和「可恢复」放在同等重要的位置。

L2 数据层

知识、法规与客户数据分开存

合规知识库、法规数据库、风险案例库、企业数据仓库与日志审计库分别存储，按敏感等级采取不同强度的保护措施，客户数据与知识数据物理隔离。

L3 服务层

核心能力做成微服务

合规评估引擎、脱敏算法服务、风险预警、数据确权与应急处置独立部署、独立扩容，通过 API 网关统一对外，单个服务升级不影响整体运行。

L4 应用层

客户看得见、用得上的那一层

合规审查平台、脱敏处理工具、风险监控大屏、客户管理门户与报告生成系统，同时支持 Web 与移动端，按角色提供差异化界面。

脱敏算法MASKING

同样的字段，不同的脱敏打法

身份证号和交易金额的脱敏目标并不一样：前者要挡住身份，后者要保住统计规律。算法选型从数据类型开始，而不是从工具箱开始。

三类数据，三种打法

数据类型主要技术怎么处理
身份信息类 掩码替换 + 泛化处理 身份证号、手机号等字段保留部分特征用于业务核验，同时屏蔽足以定位到个人的敏感位。
财务数据类 数据扰动 收入、交易金额等字段加入随机噪声，原始值无法被精确还原，统计特征保持可用。
文本类 命名实体识别与替换 地址、备注等自由文本先用 NLP 定位人名、地址等敏感实体，再逐处替换，避免整段删除影响阅读。

三层实现

L1 自动识别

先把敏感实体找出来

基于深度学习的命名实体识别模型自动识别人名、身份证号、手机号、地址、银行卡号等敏感实体，降低对人工逐字段配置的依赖。

L2 智能脱敏

按策略自动匹配算法

根据数据类型与脱敏策略自动选择算法与参数，批量处理不需要人工逐条设定；场景变化时，策略可以整体切换。

L3 人工复审

机器给结果，人来兜底

法学组对脱敏结果抽样复审，确认脱敏强度与法律口径一致后才交付，避免「技术上完成了、合规上不成立」。

关键性能指标

95%+敏感数据识别准确率
1,000脱敏处理速度（条/秒）

性能与安全的取舍

实现复杂度决定落地成本

掩码替换与泛化处理实现简单、性能高，适合快速覆盖大量结构化字段；差分隐私复杂度高，通常只用在统计发布等少数关键场景。

加密脱敏安全强度最高，但脱敏后数据可用性低，只适合存储与传输环节。业务侧仍需要一份可用性足够的脱敏视图。

组合优于单选

同一份数据里，身份字段走掩码、金额走扰动、备注走识别替换，最终对外只呈现一套一致的脱敏结果。

选型不是找最强的，而是找最匹配场景的——把安全强度、可用性和性能一起考虑进去，再写进交付清单。

监测系统MONITORING

监测四层，从采集到预警

监测系统的价值不在于记录一切，而在于从海量日志里挑出真正该报警的那几条，并且让处置动作赶在损失扩大之前。

第 1 层

数据采集

接入数据访问、传输与使用日志，支持 API 集成、日志文件解析与数据库审计等多种采集方式。

第 2 层

行为分析

用行为基线建模建立「正常长什么样」，再比对访问频率、时间、范围与数据量上的偏差。

第 3 层

异常检测

孤立森林、LOF、AutoEncoder 等算法对异常行为分类分级，判断严重程度与潜在影响。

第 4 层

预警响应

多渠道推送预警，必要时自动阻断异常访问、隔离受影响数据，为人工处置争取时间。

预置的风险场景规则

场景监测什么
批量数据导出超出日常导出量级的数据导出行为
非工作时间访问在非工作时段访问敏感数据
越权访问账户权限与可访问的数据范围不匹配
异常跨境或外部传输未报备的跨境传输或向外部地址传数据

规则按企业业务特点调整，接入后先用一周时间跑基线，再启用告警。

从预警到处置

30 分钟预警，1 小时处置

命中规则后 30 分钟内推送预警至企业联系人，并同步通知项目组；确认事件后 1 小时内启动应急处置流程。

预警信息包含风险类型、等级、影响范围与处置建议，企业联系人拿到就能判断先做什么。

处置动作由企业确认

需要停服隔离时，由企业确认后执行，避免误伤业务；处置结束形成复盘记录，用于后续规则调优。

监测规则按季度复核，业务变化、系统上线或人员调整时同步更新，不把规则设完就不管。

数据安全SECURITY

先把自己的数据管好

客户把数据交给我们，意味着把一部分风险也交给了我们。传输、存储、权限、审计、应急，每一环都要能对外交代清楚。

环节做法说明
传输安全TLS 1.3 加密协议所有数据通信加密，防止传输过程中被窃取或篡改。
存储安全AES-256 加密存储密钥由专用密钥管理系统（KMS）独立管理，密钥与数据分离存储。
访问控制RBAC + MFA基于角色的访问控制配合多因素认证，按最小权限原则授权，权限变更留痕。
审计追踪全量操作日志谁、在什么时间、对哪些数据做了什么，都可以查。
应急响应预案 + 定期演练覆盖数据泄露、系统故障与网络攻击等场景，1 小时内启动处置。
认证规划ISO 27001、等级保护 2.0计划在运营第一年推进体系建设与申报准备，目前处于规划阶段。

认证与测评由具备资质的第三方机构依据国家标准实施并出具结论。数商按规划推进体系建设、申报与整改，不对认证或测评结果作出承诺。

为什么先管好自己的数据

做合规服务的人自己先要经得起检查。客户数据进入我们的环境后，访问权限按项目分配，项目结束即回收；密钥和业务数据分开存，运维人员也看不到明文。

这些措施会写进服务合同的数据处理条款，客户可以随时要求查看权限清单和操作日志。
